# 架构与业务闭环

```mermaid
flowchart LR
  U[研究员输入代码 / 日期 / 策略参数] --> API[FastAPI 审计 API]
  RA[RD-Agent(Q) / Qlib 因子研究] -->|导出日期分数 JSON| API
  API --> P[AkShare 行情 Provider]
  P --> S[(内容寻址 CSV 快照<br/>SHA-256)]

  SIG --> FB[framebt 因果回测引擎<br/>MIT 固定 commit]
```

## 模块职责

- **Provider**：获取 AkShare A 股日线，归一化字段并保存快照。各实现共用同一份 DataFrame，防止数据差异污染实现差异。
- **RD-Agent(Q) handoff**：从其独立 Qlib 研究环境导出 `date,score`，转换为 JSON 导入。本应用记录来源、实验 ID 与分数 SHA-256；按阈值转成目标持仓，不执行因子代码。
- **信号层**：收盘后计算快慢均线状态，次日开盘执行。策略信号确定化，避免模型输出影响复算。
- **framebt**：固定上游 commit，负责因果回测、延迟成交、A 股规则/成本模型、权益曲线和成交记录；由适配层将 AkShare 日线映射成 BarFeed。
- **事件账本 / 批量账本**：项目内两条独立重放路径，互相核对并产生一致性门禁。由于与 framebt 的执行和费用口径并非完全相同，framebt 目前作为独立曲线参考，不参与这一门禁。
- **审计层**：对齐日净值、逐笔成交、计算最大差额，并由阈值生成 PASS/BLOCK。当前 PASS 门槛为净值最大差异不超过 0.01 元且成交记录一致。
- **Agent**：LangGraph StateGraph 编排确定性规则解释节点和可选模型节点。默认只运行规则节点；用户明确勾选后最多调用一次兼容模型，输入上限为 4 条证据，失败时回退到规则摘要。
- **界面**：展示快照来源、两套内部账本曲线、framebt 外部引擎曲线、门禁、成交账本、差异证据和限制说明。

## 当前假设与生产前工作

目前策略输入是双均线或 RD-Agent(Q) 导出的单标的分数阈值信号，不提供选股或投资建议。RD-Agent(Q) 以结果交接方式集成，研究循环仍在独立环境运行；Qlib 的多标的打分与这里的单标的目标状态语义并不等价，尚需完整 adapter 才能声称端到端复用其原生组合。framebt 与项目内账本口径差异需用黄金样本建立映射。生产化还需授权行情、复权和公司行为数据、完整交易规则、评测集、运行隔离、权限审计和任务队列。
